# 在 NHN Vocoder 中引入 Transformer 的评估方案

> 状态：设计与实验方案，尚未实现或验证音质。范围仅限 `Melo.Vocoder` 的特征到波形生成；不涉及歌词、音符到特征的上游声学模型。

如果想先理解特征提取、整体编码、可选分组编码和 Transformer 的关系，请阅读 [特征与 Transformer 原理说明](transformer-feature-flow-explained.md)。首版采用现有 72 维特征整体输入，分组编码留作后续实验。

LF／Rd 声源、神经非周期生成、瞬态支路以及它们与本文的独立对照关系，见 [Vocoder 声源与时间建模改进方案](vocoder-source-and-conditioning-improvements.md)。本文仍专门评估合成端的时间上下文增强。

## 1. 要回答的问题

当前 NHN 风格声码器将 LLSM72 特征变为 48 kHz 单声道波形。引入 Transformer 的目的，是检验更宽的**帧级时间上下文**能否改善歌声合成中的长音音色、滑音、气声和辅音过渡，并量化增加的训练与推理成本。

实验必须分别回答：

1. 在**相同 LLSM72 输入、相同波形目标**下，Transformer 是否比现有卷积条件网络改善音质？
2. 如果改善，收益是否来自更宽的上下文，还是仅来自更多参数和计算？
3. 分块、导出、CPU/GPU 推理是否仍满足项目的部署需求？

这一实验不检验 LLSM 的替代方案。把 Transformer 接在 LLSM72 后面，仍需 `pyllsm2` 制作新训练数据及分析 WAV 输入；已有 LLSM72 的纯特征推理则无需在推理时调用它。更换特征体系应单独立项，避免同时改变输入和网络后无法判断结果来源。

## 2. 现状与可能的收益

现有生成器见 [`../src/core/model.py`](../src/core/model.py)：`input_normalizer` 和 `input_proj` 后由 `primary_wn` 生成帧级隐藏状态；`spectrum_gen` 用它预测三路动态 FIR，`noise_proc` 用它预测十段噪声增益。之后分别生成谐波、噪声和瞬态激励，经 FIR、16 子带 PQMF 和 `secondary_wn` 得到波形。

`primary_wn` 目前由三层核长为 3、膨胀率为 `(1, 3, 9)` 的非因果卷积组成。仅计算这段条件网络，感受野为 `1 + 2 × (1 + 3 + 9) = 27` 帧。默认 `48_000 / 256 = 187.5` 帧/秒，约为 **144 毫秒**。这不是整个声码器的严格总感受野：后面的 FIR、PQMF 和 `secondary_wn` 也使用邻域，F0 相位由累加得到。它只说明当前**帧级条件预测**直接观察的局部范围。

| 候选收益 | 需要验证的具体现象 | 现有结构中的作用点 |
| --- | --- | --- |
| 长音的音色稳定性 | 长元音是否出现能量、气声或高频纹理的不自然波动 | 动态 FIR、噪声增益的跨帧决策 |
| 滑音和颤音连续性 | F0 变化时谐波与噪声是否出现跳变或金属音 | FIR 系数随时间的连续性 |
| 辅音到元音的衔接 | 清辅音、爆破音和换气是否被抹平或拖尾 | 瞬态、谱形和噪声分支 |
| 低带宽输入的条件利用 | BWE 模式中高频纹理能否更连贯 | 条件网络对相邻帧的利用 |

这些是待证实的假设。Transformer **不会**自动纠正错误 F0、恢复原始音频中不存在的信息，或代替已有的谐波激励、FIR、噪声源和 PQMF。额外上下文也可能平滑掉瞬态，造成更慢的推理。

## 3. 首选接入方式

第一轮只在帧级加入一个非自回归 Transformer 编码器：

```text
LLSM72 [B,T,72]
  ├─→ physical：原始 F0、VUV、BAP，继续供显式激励使用
  └─→ input_normalizer → input_proj → 小型 Transformer → primary_wn
                                                ↓
                                spectrum_gen / noise_proc
                                                ↓
                         现有谐波、噪声、FIR、PQMF、secondary_wn
                                                ↓
                                   waveform [B,1,T×hop]
```

Transformer 只增强可学习的隐藏状态。原始特征仍单独进入 `_harmonic_source`、`_noise_source` 和瞬态计算，避免注意力层改变 F0、VUV、BAP 的物理含义。输入和输出的 `T` 保持一致，合成长度仍为 `T × hop_length`。保留 `primary_wn`，有助于加载已训练的基模并做小改动对照；若有效，再测试由 Transformer 直接替代 `primary_wn`。

建议先做小规模参数搜索，而不是直接引入大型序列模型：

| 项目 | 首轮候选 | 原因 |
| --- | --- | --- |
| 层数 | 2、4 层 | 比较收益与显存、耗时变化 |
| 隐藏宽度 | 128、256 | 与现有 256 通道量级接近；实际参数量要记录 |
| 注意力头数 | 4 | 保持每头宽度合理 |
| 注意力范围 | 从 256 帧窗口开始 | 默认约 1.37 秒；避免长音频全局注意力的平方成本 |
| 时间位置 | 相对位置或明确的帧偏移 | 避免分块时每块都从零开始导致位置含义变化 |
| 初始化 | 残差旁路起步，新增分支初始影响接近零 | 便于对已有基模做受控微调 |

这些数值只是实验起点，不是已测得的最优配置。先在目标设备上测训练显存、每 step 时间和推理耗时，再决定是否扩大窗口。注意力放在**特征帧率**上，不能直接对 48 kHz 逐采样点做全局注意力。5 秒输入约 938 帧、10 秒约 1875 帧；直接全局注意力的计算与中间矩阵会随帧数平方增长。

## 4. 对照实验

固定同一批 LLSM72/WAV 配对数据、F0 后端、训练/验证/测试划分、采样率、hop、随机种子、训练目标和步数。每个模型都从相同训练策略运行；如果从已有权重微调，基线也做等步数微调，并另报从头训练结果。不要用不同 checkpoint 的最佳训练时长混合比较。

| 组别 | 模型 | 目的 |
| --- | --- | --- |
| A | 当前 `NHNVocoder` | 建立质量、速度和资源基线 |
| B | A + 小型 Transformer 帧级编码器 | 测试注意力带来的增益 |
| C | A + 参数量/上下文尽量匹配的扩张卷积编码器 | 检查 B 的收益是否只是更多容量或更长上下文 |
| D（可选） | 用 Transformer 替代 `primary_wn` | 仅在 B 有收益时评估是否可简化结构 |

现有 [`../configs/nhn-prototype-5-10h.yaml`](../configs/nhn-prototype-5-10h.yaml) 用 1 秒片段训练。它能跑通原型，却不足以充分测试 1 秒以上的上下文：第一轮可用它进行形状、梯度和初步音质验证；正式对照应增加 2 秒及更长片段，并让 A/B/C 使用相同片段长度。显存不足时先减小 Transformer 宽度或注意力窗口，同时保留同等的测试集和推理条件。

数据按歌曲、录音 session 或原始长文件分组，避免相邻裁片同时进入训练和测试。独立测试集应至少覆盖普通元音、长音、滑音/颤音、清辅音、气声/换气、高音以及安静段。BWE 先作为第二轮：普通 48 kHz 重建通过后，再对各来源带宽分别比较，避免把带宽补全的问题误判成 Transformer 收益。

## 5. 评测与通过条件

### 5.1 客观结果

现有 [`../src/training/losses.py`](../src/training/losses.py) 已有 waveform、多个分辨率 STFT、Mel、相位、瞬时频率和 F0 谐波损失；[`../src/inference/benchmark.py`](../src/inference/benchmark.py) 已记录 RTF、p95 耗时及内存。实验报告需逐项记录，不能仅引用训练总 loss。

另外补充：对生成波形重新提取 F0，比较有声段的音分误差及跳变；测静音段残余噪声、音量误差、齿音/高频能量；记录导出前后数值差异。用于评价的 F0 提取器与训练特征 F0 后端尽量独立，避免同一算法的偏差相互抵消。波形相位、F0、频谱指标各有局限，不能替代试听。

### 5.2 听测

在固定测试集上准备至少 20～30 个未见片段，覆盖上述音色与发声类型。按相同响度、随机顺序播放 A/B/C，盲听者不知道模型名；记录整体偏好和具体问题：长音纹理、辅音清晰度、气声、金属音、爆音、片段边界。按片段和听者汇总偏好及不确定区间，保留音频样例，避免只挑选效果好的样本。

### 5.3 预先约定的门槛

第一轮以**不破坏既有行为**为硬门槛：输出长度、采样率、有限数值、确定性种子、正常/分块推理、训练梯度和 checkpoint 加载全部通过。音质采用 A/B/C 的盲听偏好和分场景指标决定；B 只有在多个种子或重复训练中稳定改善目标问题，且没有新增明显的高音、辅音或静音伪影，才算有价值。精确的偏好差值门槛应在试听前写入实验记录，不能看过结果后调整。

性能门槛在目标部署机器上固定：分别报告 2 秒与长片段的 CPU/GPU RTF、p95、峰值内存、模型大小和整段调用返回时间；对比 A 的相对变化。当前接口返回整段 `AudioResult`，尚无逐块首帧输出。若产品要求离线合成快于实时，可将 `RTF < 1` 设为目标，但不能假定当前 A 或 B 已满足。BWE 还需逐来源采样率检查低频保真和高频伪影。

## 6. 分块、导出与权重兼容风险

现有 [`../src/sdk/session.py`](../src/sdk/session.py) 的 `synthesize_chunked` 按 `chunk_frames` 切输入，以 `overlap_frames=32` 为默认值交叉淡化音频；每块还使用不同种子。若 Transformer 关注更长范围，32 帧重叠可能不足以保证边界质量，而且每块重置的位置和上下文会改变输出。实验需对同一长句比较整段与分块结果，扫描 32/64/128 等重叠帧数，记录接缝附近能量和听感；若需要额外左右上下文，应显式区分“供模型观察的帧”和“提交给结果的帧”。现有分块函数是离线拼接，不等同于低延迟流式推理。

新增 Transformer 参数会改变 checkpoint 的模型结构。应在配置中显式记录 `condition_encoder` 类型和超参数，使旧 checkpoint 默认走原卷积分支；新增参数的旧权重加载需要受控迁移，不能依赖忽略所有缺失参数。恢复训练时，新增网络的优化器状态也不能冒充完整恢复。保存模型格式、推理包装与测试须同步更新。

[`../src/inference/export.py`](../src/inference/export.py) 当前使用 `torch.jit.trace(..., check_trace=False)` 导出 TorchScript，ONNX 导出使用固定示例帧数。加入窗口注意力或位置编码后，要用**不同于跟踪示例**的帧长、跨窗口长度和分块输入验证导出结果与 PyTorch 推理一致；尤其检查遮罩、动态 shape、位置偏移及长音频内存。不能仅以“导出文件成功生成”作为通过。

## 7. 实施顺序与交付物

1. **基线记录**：冻结数据划分、A 的配置/权重、音质样例及 CPU/GPU 基准。仓库当前未附带可直接评价音质的预训练权重，若没有项目自有 checkpoint，需先训练 A。
2. **最小原型**：实现可关闭的帧级 Transformer 分支，检查输入输出形状、反向传播、保存/加载和短片段推理；先不改特征格式。
3. **受控训练**：按第 4 节训练 A/B/C，记录训练时间、显存、各项损失和验证样例。
4. **听测和部署检查**：完成盲听、长句/分块、TorchScript/ONNX、目标机器基准及 BWE 第二轮。
5. **决策**：若 B 相对 A、C 在目标场景里有可重复的改善且达到性能门槛，再决定保留或替代 `primary_wn`；否则保持卷积结构，并据失败样例判断是否优先改特征、激励或损失。

最终报告至少包含：数据清单与划分哈希、实验配置和随机种子、checkpoint 标识、客观指标、逐场景盲听结果、音频样例、整段/分块差异、目标设备性能，以及明确的保留或回退结论。
