# NHN Vocoder 推荐数据量与训练机器

本文给出当前 NHN Vocoder（LLSM72 → 48 kHz WAV）的数据和硬件建议。数值是用于制定
实验预算的工程建议，不是固定门槛；最终应以自己的音色范围、数据清洁度和目标机器实测为准。

## 先给结论

如果目标是先训练一个可听、可继续迭代的单人歌声音色，建议从以下组合开始：

- 20～50 小时经过清洗的 48 kHz 干声；
- 单张 24 GB 以上 CUDA GPU，32 GB 显存更从容；
- 12～24 核 CPU、64 GB 内存、2 TB NVMe SSD；
- `batch_size: 1～2`、`segment_seconds: 1～2`，先只跑重建阶段，再启用 GAN；
- 先训练[基模](../configs/nhn-base.yaml)，基模稳定后再训练
  [DSP 控制头](../configs/nhn-dsp-post.yaml)。

当前训练器是单进程、单设备实现。购买多张 GPU 不会自动加速，除非后续加入 DDP/多卡训练。

## 推荐数据量

### 单说话人或单歌手

| 阶段 | 去除静音后的有效时长 | 可以验证什么 | 不应期待什么 |
| --- | ---: | --- | --- |
| 冒烟测试 | 10～30 分钟 | 管线、维度、保存和恢复是否正确 | 泛化能力和稳定音质 |
| 小规模过拟合 | 30～90 分钟 | 模型能否记住音色、损失是否下降 | 未见音高和发音的自然度 |
| 原型 | 2～5 小时 | 基础可懂度、初步音色和高频表现 | 稳定商用品质 |
| 可用基线 | 10～20 小时 | 大部分常见音域与发音 | 极端高音、气声和复杂转音完全稳定 |
| 推荐正式训练 | 20～50 小时 | 较稳定的单人歌声基模 | 数据分布之外的演唱方式 |
| 高覆盖版本 | 50～100 小时 | 更完整的音域、力度、唱法和辅音覆盖 | 用重复或低质量数据换取提升 |

对这个任务，20 小时风格丰富、录音一致的干声，通常比 100 小时带混响、削波、伴奏泄漏或
大量重复句的数据更有价值。统计时使用“清洗后真正送入训练的有效音频时长”，不要使用原始
工程文件总时长。

### 多说话人或通用基模

- 建议总量从 100～300 小时起步；更强调泛化时可继续扩大到 500 小时以上。
- 每位核心说话人最好至少 2～5 小时，避免少量说话人只作为噪声参与训练。
- 采样时平衡说话人、音域、性别、唱法和语言，不要让数据量最大的说话人占据绝大多数 batch。
- 当前模型没有显式 speaker embedding。若要做真正的多音色可控基模，需要先扩展条件输入和
  checkpoint schema，而不仅是把多人的 WAV 混在一起训练。

### 16 kHz 输入、48 kHz 输出的 BWE 数据

BWE 训练必须从真实 48 kHz 母带生成低带宽条件，target 始终保留原始 48 kHz：

```bash
uv run nhn-vocoder preprocess --pipeline bwe masters_48k data/bwe_train \
  --source-sample-rates 8000,12000,16000,22050,24000,32000,44100,48000
```

推荐至少使用 20～50 小时不同音域和发声方式的 48 kHz 母带。八种采样率变体只是同一批内容的
带宽增强，不等于获得了八倍独立语音；评估集必须按原始歌曲或原始录音分组切分，不能让同一条
母带的不同采样率版本同时落入训练集和验证集。当前预处理器已经按原始 ID 分组切分。

## 数据质量要求

训练母带建议满足：

- 48,000 Hz，单声道；PCM 16-bit、24-bit 或 float WAV 均可，预处理后统一写 WAV。
- 尽量使用干声，避免不可逆混响、母带限制器、伴奏泄漏、降噪金属音和编码伪影。
- 不应削波；峰值建议留约 1 dB 余量，但不要对每个切片分别做激进响度归一化。
- 保留气声、清辅音和自然换气，它们是噪声分支与 BAP 学习所需的信息。
- 删除全静音、错采样率、损坏、重复和明显错标文件。
- 训练/验证/测试按歌曲、录音 session 或原始长文件分组，避免相邻切片泄漏。

建议划分：约 90% 训练、5% 验证、5% 最终测试。小数据集至少预留 20～30 分钟验证集和
30～60 分钟测试集；测试集不要参与参数选择或 feature statistics。

## 磁盘容量估算

48 kHz mono PCM16 WAV 约为 0.35 GB/小时。hop=256 时，float32 LLSM72 特征约为
0.19 GB/小时，因此普通 WAV+NPY 配对数据约为 0.55 GB/小时，不含原始文件、日志和
checkpoint。

BWE 预处理只保存一份 48 kHz target，但会为每个来源采样率保存一份 LLSM72。使用八种采样率时，
输出数据约为 `0.35 + 8 × 0.19 ≈ 1.9 GB/小时`；再计入原始母带、临时文件和余量，建议按
2.5～3 GB/小时规划。50 小时 BWE 工程至少预留 150 GB 数据空间，整机使用 1～2 TB NVMe
会更方便反复实验。

## 训练显存为什么远大于模型文件

约 12 MB 指的是推理权重规模，不等于训练显存。训练还需要保存：

- 48 kHz 长序列上的中间激活；
- 反向传播梯度和 optimizer state；
- 动态 FIR/PQMF 的临时张量；
- GAN 阶段的 MPD/MSD 判别器、feature maps 和对应优化器。

显存通常随 `batch_size` 和 `segment_seconds` 接近线性增长。显存不足时，按以下顺序调整：

1. 将 `batch_size` 降为 1；
2. 将 `segment_seconds` 从 2.0 降为 1.0，再降为 0.5；
3. 保持 `amp: true`；
4. 增大 `gan_start_step`，先确认纯重建训练稳定；
5. 最后再考虑梯度累积、activation checkpointing 或多卡改造。

## 推荐训练机器

### 最低调试机器

- GPU：12 GB CUDA 显存；
- CPU：8 核以上；
- 内存：32 GB；
- 磁盘：500 GB SSD；
- 建议配置：`batch_size: 1`、`segment_seconds: 0.5～1.0`。

适合验证预处理、过拟合小样本和检查 checkpoint，不建议直接承担 20～50 小时正式 GAN 训练。

### 推荐单卡工作站

- GPU：24～32 GB CUDA 显存；
- CPU：12～24 核；
- 内存：64 GB；
- 磁盘：2 TB NVMe SSD；
- 建议配置：从 `batch_size: 1～2`、`segment_seconds: 1～2` 开始实测。

32 GB 显存的 GeForce RTX 5090 是当前可选的单卡档位之一；NVIDIA 官方规格同时给出 575 W
显卡功耗和 1000 W 建议系统电源，因此机箱、供电和散热也必须一起规划：
[RTX 5090 官方规格](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5090/)。

### 大显存工作站或云端

- 48 GB：适合更长 segment、更大 batch 和并行做模型/损失实验；
- 80～96 GB：适合大规模超参数搜索、未来扩大网络或加入多说话人条件，但对当前约 12 MB
  单模型并非必需；
- 企业工作站可参考 96 GB ECC 的
  [RTX PRO 6000 Blackwell](https://www.nvidia.com/en-us/products/workstations/professional-desktop-gpus/rtx-pro-6000/)；
- 云端可参考 80/94 GB 的
  [NVIDIA H100](https://www.nvidia.com/en-us/data-center/h100/)。

当前训练代码没有 DDP，因此优先选择“一张显存足够的 GPU”，而不是两张显存较小的 GPU。
云端租用时先用 500～1000 step 测速，再决定是否长租。

### CPU 与 Apple Silicon

CPU 推理快不表示 CPU 训练也快。正式训练包含反向传播、STFT 损失和多个判别器，仍优先 CUDA。
CPU 或 Apple MPS 适合功能验证和短实验；若 MPS 遇到不支持的算子或混合精度异常，将配置中的
`device` 改为 `cpu`、`amp` 改为 `false` 进行定位。

## 推荐执行顺序

1. 用 10～30 分钟数据完成预处理和冒烟训练。
2. 用 30～90 分钟数据过拟合，确认模型确实能重建音色。
3. 扩展到 2～5 小时，确定 F0 后端、损失和 GAN 启动 step。
4. 固定配置后再投入 20～50 小时正式训练。
5. 在独立测试集评估，再进行 DSP 后训练和模型导出。

对应操作入口与完整命令见项目 [README](../README.md)，数据和采样率协议见
[输入扩展与 SDK 规划](vocoder-input-sdk-plan.md)。
